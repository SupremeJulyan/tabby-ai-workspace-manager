# 性能审查与验证

基线为 `5a9b06f`（2026-10-28），开始修改前已通过 `git fetch origin` 确认本地 `main` 与远端一致。本次改动聚焦工作区恢复、远程目录读取、Git 扫描和文件读写，不改变原有保存冲突、权限检查及未确认保存的处理。

## 已落实的优化

| 路径 | 原有开销 | 改动 |
| --- | --- | --- |
| 切换已缓存工作区 | 恢复文件和 AI 窗格之前等待目录刷新 | 立即使用已有目录树恢复，后台重新读取；终端切换目录与界面恢复同时进行，仍防止重复切换 |
| 展开目录刷新 | 逐个等待每个已展开目录 | 最多并发 4 个目录读取，保持原有显示顺序；离开工作区或被新刷新替代时取消旧请求并阻止排队任务启动 |
| 文件页连接恢复 | 会话池认证完成后仍可能等待 100 ms 轮询 | 认证完成立即唤醒；终端尚未注册时仍保留轮询，关闭页面会清理等待和定时器 |
| Git 仓库根目录发现 | `rev-parse` 后继续读取目录寻找 `.git` | 明确位于仓库根目录且不扫描嵌套仓库时直接返回；路径别名和符号链接仍做范围确认 |
| Git 子目录枚举 | 路径解析与限量列目录分别发 SSH 请求 | 合为一次 SSH exec，保留路径检查、输出上限、条目上限和取消处理 |
| Git 分支、历史及同步状态 | 重复探测 HEAD；已同步仓库仍遍历提交历史 | 分支查询批处理；正常历史直接读取，失败时才检查是否尚无提交；相同提交 ID 跳过差异遍历，存在双向差异时批量读取 |
| SFTP 文本保存 | 为整个文件分配 UTF-8 Buffer，再分片发送 | 用最多 256 KiB 的缓冲区逐段编码；ASCII 文件保持原有发送次数，UTF-8 多字节序列与代理对不会被截断 |
| SFTP 文本及预览读取 | 缓存全部分片，再完整拼接一次 | 填充一个已知大小的自有缓冲区，保留 EOF、文件增长/缩小和取消检查 |
| SSH shell 保存回退 | 分别取得最终大小和版本 | 用同一次 `stat` 返回值完成两项检查 |

SFTP 保存仍采用原地写入，保留原有权限与文件属性处理、冲突检测、30 秒超时及断线后的“保存未确认”状态。当前 Tabby/russh 文件句柄没有公开带偏移写入接口，因此保持顺序写入，避免并发修改同一句柄的位置。

## 对比结果

环境：Linux，Node.js `v26.12.1`，每项运行 5 次取中位数。基线源码在独立临时目录中编译；两个版本使用同一套基准脚本。

Git 使用真实本机 Git 和 POSIX shell，每个模拟 SSH exec 注入 50 ms 延迟。SFTP 使用内存中的模拟文件句柄，测量编码、复制开销及缓冲区大小，**不包含真实网络与磁盘耗时**。

| 场景 | 基线 | 优化后 |
| --- | ---: | ---: |
| 仓库根目录发现 | 162.0 ms / 3 次 exec | 54.6 ms / 1 次 exec |
| 单个目录的限量枚举 | 107.8 ms / 2 次 exec | 55.8 ms / 1 次 exec |
| 与上游同步的仓库：分支、历史、同步信息 | 328.9 ms / 10 次 exec | 164.6 ms / 5 次 exec |
| 32 MiB ASCII 文本读取（内存模拟） | 41.0 ms | 21.4 ms |
| 32 MiB ASCII 文本保存（内存模拟） | 16.7 ms | 2.9 ms |
| 上述保存操作的最大编码缓冲区 | 32 MiB | 256 KiB |
| 上述保存操作的写请求数 | 128 | 128 |

缓冲区指标是传给文件句柄的实际底层 ArrayBuffer 大小，不代表整个编辑器的总内存；编辑器仍持有原文和当前文本。读取基准中的 Node external-memory 采样受 GC 影响，两个版本的增量中位数均为 32 MiB，未据此宣称进程峰值内存下降比例。

原始记录见 [performance-results.json](performance-results.json)。这些结果证明请求数与本机处理开销减少，不等同于真实服务器的端到端加速比例；本次未进行真实 Tabby 界面或 SSH 网络实测。

## 复现

在项目根目录执行（Git/SSH 模拟基准需要 POSIX shell 及项目原有的 GNU 远端工具）：

```sh
npm run check
node --expose-gc scripts/benchmark-performance.mjs --rtt 50 --samples 5
```

对比其他版本时，先独立编译该版本，再让同一脚本加载它的 `.build`：

```sh
node --expose-gc scripts/benchmark-performance.mjs --build-dir /path/to/baseline/.build --rtt 50 --samples 5
```

## 回归验证

本机 `npm run check` 完成构建并通过 360 项测试，另有 2 项按测试条件跳过。新增覆盖包括：

- 缓存工作区不等待慢速重读、并发目录读取上限与顺序、取消后不继续启动排队请求。
- 会话池认证完成即时唤醒，不依赖下一次轮询。
- Git 请求数量、仓库根目录快速发现、已同步/领先/落后状态和提交标记。
- 合并 SSH 请求后仍验证真实路径，拒绝控制字符及末尾换行的符号链接目标。
- SFTP 缓冲区所有权、读取途中增长/缩小、关闭页面取消、保存时分片编码与代理对边界。

原有保存冲突、权限与文件属性、断线、超时、Git 操作和插件打包安装测试一并通过。Node.js 22/24、macOS、Windows 及真实 SSH 的表现需由对应 CI 或实机验证。
